## What you learned — beyond this solution

The claims case was the vehicle. These transfer to whatever you build next:

- **A complete brief makes a quiet agent.** Every answer the planner never had to ask for was an answer you supplied up front.
- **One document, one question.** Requirements, design, plan — each written once, referenced everywhere, brought to as-built at the end.
- **Contracts before consumers.** The cheapest half of an interface is the shape — settle it first, and stand-ins can prove the wiring before the real thing exists.
- **Gates are commands, and every gate is a floor.** Scripts catch the boring half; *go and look* catches the rest; the agent's "done" is an opinion.
- **Restraint is the hard half of automation.** A process that flags something on every claim has automated nothing — the clean path settling untouched was your hardest test.
- **Write as you go.** Context windows fill; `PROGRESS.md` outlived every session that wrote it.
- **The screen is the product.** Whatever the architecture says, the two reviewer screens are what anyone will ever see — taste is a requirement you state.
- **Done means the next person can start** — a pinned version, an as-built design, a runbook.

## On speed, honestly

You just built in a day what the PDD budgeted at 25 person-days — that first-hand experience is worth more than any statistic. The wider evidence points the same way, with a hedge worth keeping: as UiPath's CEO puts it, coding agents "compress the first 10% of the work — what's left is the hard part," because "writing code is the easy part; running it, durably, safely, at enterprise scale, is where the value accrues." Most developers are already there — the Stack Overflow 2025 survey has 84% using or planning to use AI tools. The operating model you practiced today is the part that makes the speed usable: **AI proposes. Humans decide. Automation executes.**
